You might have noticed people bitching about GitHub being down again. It can't be helped ... There are literal slop factories today gushing out slop 24/7 and furthermore it's operated by Microsoft for some time now.

Radicle is an alternative to centralized forges. It offers 24/7 uptime(*) by its decentralized design. No more centralized control over your codebases. You retain all the control over who seeds your code and who (or no one) you want to seed personally. Sharing is caring 🏴‍☠️

* if people seed your stuff

I think it's an interesting technology you SHOULD know about.

How does Radicle actually compare to GitHub

I like to think about Radicle like this:

Radicle is to GitHub what torrenting is to direct download.
  • It cannot be shut down as long as peers exist
  • Repos are automatically replicated across all peers in the network (peers which are OK with your repo)
  • It features a built-in Tor support for your spiciest repos
  • It's fully open source and a collaborative effort
  • It offers public and private repos
  • You can open and collaborate on issues, they live inside git repos
  • Pull requests are done with patches using git commands, they are just git patches
  • Users are identified by their decentralized identity (DID) encoded from their ed25519 key
  • Repos are identified by a deterministically derived ID from their signed metadata.

Complete flow

Think what you usually do with git and GitHub; init a repo, do some commits, push your code to the remote, open an issue / PR, close them, merge them. For me that covers 95% of stuff i do. "Complete flow" of course is an oversimplification, there is much more, but this will get you started. To go into more detail do check out Radicle User guide and Radicle Protocol guide.

1. Setting up Radicle

Go to Get started section of Radicle and install it on your system.

At the time of the writing its as simple as running:

curl -sSLf https://radicle.dev/install | sh

If you prefer not to run scripts from the web you can just get it from the source.

After that, you will need to create your identity. You do that by running:

rad auth

Make sure the password is something you will remember, you WILL be prompted to input it at certain times like when starting the local node.

To get info on your identity like your DID and other details just run:

rad self

There is also a Radicle Desktop fully featured graphical client. It gives you a bunch of stuff you might expect like file explorer, diff viewer, listing issues etc.

2. Repo setup

Pick any repo - new or old it doesn't matter as long as it is an initiated git repo. If it's not yet, then run:

git init

To then initiate it as a Radicle repo, run:

rad init

After confirming the details, you will be given some info and a string such as rad:z43dViVwFh1XTPx9E7MAmyEjx8KR6, this is the ID of your Radicle repo.

3. Syncing, committing and pushing

You initialized your repo but it's nowhere to be found on the net ... because we havent pushed anything yet. Make an empty commit or something and then lets push it to the remote.

# ... git commit --allow-empty -m "init"

For this illustration it does not really matter whats in the commit, it can be empty.

For that you will need to run a local Radicle node. Radicle is offline-first (git actions, creating repos, etc. can all be done offline), but for stuff like pushing commits to the Radicle network, you will need to run a local node. Simply run:

rad node start

At the time of writing, the two default preferred seeds (rosa.radicle.network and iris.radicle.network) have issues with connections due to the surge of people taking interest in Radicle. If you need to find additional seeds check the seeds list on Radicle's Zulip chat. To add seeds to you node simply find the seed and add it as such:

rad node connect z6MkuyPDChcwCruKGd2tw54FZo2HemY135JvTLzbVTvoWKJR@index.radicle.garden:8776

This will connect your local node to another node and your repo will propagate.

You can now simply push via:

git push # or if you have multiple git remotes git push rad main

and it will push your stuff on the Radicle network.

If you inspect your remotes you will see something like:

$ git remote -v rad rad://z49w1NV6sraK7D4878VJq4iNXWeTD (fetch) rad rad://z49w1NV6sraK7D4878VJq4iNXWeTD/z6MkqoMEQuzmqbykE7pWpK26asi8h... (push) # the thing after slash is your node id

4. Opening & managing issues

Radicle is a decentralized protocol. There is no single server like GitHub where your issues or pull requests live and die. It uses something called COBs (collaborative objects) that live in the repo itself.

To open a new issue, simple do:

rad issue

It will prompt you to add title and description. If you want a one-liner you can do:

rad issue open --title "Issue Title" --description "Issue Description"

Bam, if you have local node set up it will automagically sync your issue to the seeds.

Likewise, to close it, assign it to someone, do:

# mark an issue as solved rad issue state $ISSUE_ID --solved # mark an issue as closed rad issue state $ISSUE_ID --closed # add a new assignee to the issue rad issue assign $ISSUE_ID -a did:key:$USER_DID # use `--help` to see a bunch of other options available rad issue --help

5. Opening and managing Pull requests

There are no "pull requests" on Radicle. There are patches. To open a new patch to the repo: branch off, make a commit and make a patch via:

git push rad HEAD:refs/patches # doesn't need to be HEAD specifically, it can be whichever branch

To list all patches, run:

rad patch list # or for specific patch rad patch show 0309b33

To merge a patch back, just check its commit, merge / rebase to your branch and push. Simple. Radicle will take care of propagating the change to the seeds.

In case you need a new identity

If you ever need a new Radicle identity, there is currently no easy command to do that. But its simple by design so in that case you need to:

# delete the following things (relevant keys, config and node storage) rm ~/.radicle/keys/radicle.pub rm ~/.radicle/keys/radicle rm ~/.radicle/config.json rm -rf ~/.radicle/storage # create new identity rad auth # if you want to reinit the repo with Radicle git remote rm rad rad init

And that covers about everything you probably do in your day to day code forging.

Closing thoughts

Is this the new meta? Maybe, but probably not just yet. Radicle feels very much experimental still. I can see the use cases, but i can also see there is much to be done to attract any mainstream audience (and it might not come from Radicle itself either, hint).

People on Zulip where Radicle community lives were more than happy to quickly answer all questions I had. I think its cool to have a decentralized alternative, because there will come a time when enshittification gets to big centralized forges.
